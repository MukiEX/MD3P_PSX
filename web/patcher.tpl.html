What changes

  • The clown follows a virtual paddle, one column per tick, through the game's own movement code, so sounds and animations stay.
  • The clown and aim line glide between columns, and the column you point at pulses.
  • Over a column whose bottom balloon matches what you hold, the mouse slows to half speed and the NeGcon gets sticky.
  • The PS1 reads pads once per frame, so a JP3 spinner keeps up to 2 edges per frame (100 or 120 per second); faster turns need an adapter that paces its edges.
  • Options gains a MOUSE SPEED row. Card select, name entry and the language screen accept the mouse and the NeGcon.
  • All hidden characters are unlocked. All six languages are patched.
The idea

A paddle for a game that never had one

The Neo Geo Paddle Edition turns the clown in Magical Drop III into something you steer with a spinner, the way Taito's arcade puzzle games played. The PlayStation has no spinner, but it does have controllers that measure motion: the Mouse, the NeGcon's twist, and Namco's Volume knob. This patch teaches the European disc to read all three, plus a JP3-style spinner wired to a pad's d-pad, and to use any of them as a paddle.

The rule from the start was to change as little of the game as possible. The clown still moves through the game's own code, so every sound, animation and rule stays as it was. The patch only decides when the clown should step left or right, and draws it gliding between columns.

Step 1

Reading the disc

The disc has one data track. It boots a small language selector, which then loads one of six copies of the game: English, French, German, Spanish, Italian or Dutch. The six copies contain the same game code with addresses shifted by a few bytes, so the patch is written once, against the English copy. A build script finds each spot it needs in the other five by searching for the surrounding instructions with the shifting numbers masked out. Before writing, it checks the original instructions are exactly what it expects, so it can never patch the wrong place.

The patched files are written back over the originals, the same size and in the same place on the disc. Only the changed sectors get new error-correction data. That keeps the patches small and lets this page work on a CHD without rebuilding it.

Step 2

Hearing the controllers

The game read its pads through the BIOS, which only ever reports buttons. A mouse's movement or a NeGcon's twist never reached it. The first job was swapping that for the PlayStation's library pad driver, which hands back each controller's raw report every frame. A small reader then rebuilds the exact button word the game always used, so nothing else in the game had to change.

That reader is also where each port's controller is identified:

  • Mouse has its own ID.
  • NeGcon and Volume send the same ID and the same report. A Volume physically can't press I, II, L, the d-pad or several other inputs, so a port is treated as a Volume until one of those shows up on several reads in a row. Then it's a NeGcon until it's unplugged.
  • JP3 spinner: a spinner wired to LEFT and RIGHT will eventually report both at once, which a real d-pad can't do. The first time that happens, the port switches to spinner mode, the same rule the Neo Geo version uses.
  • Anything else stays a normal pad, unchanged.

Real hardware added one lesson. Controller reads sometimes fail or come back garbled, which made a Volume flicker between "NeGcon" and "Volume". Now a failed read repeats the last good one, garbage is ignored, and a port only counts as unplugged after 30 failed reads in a row.

Step 3

Turning motion into a paddle

During play the patch keeps a virtual paddle position, 128 units for each column. Mouse and spinner movement nudge it; the NeGcon twist and the Volume knob set it directly, wall to wall. When the position crosses into another column, the patch presses LEFT or RIGHT for the game for one tick, and the clown walks there normally.

  • Hysteresis: you have to go a little past a column's edge before it counts, so a shaky hand doesn't make the clown jitter.
  • Glide: the clown and the aim line are drawn at the paddle position (never more than a column from the real one), so movement looks smooth instead of snapping.
  • Pulse: the column you're aiming at gently pulses, using the brightness the game already uses for its fades.
  • Magnet: over a column whose bottom balloon matches what you hold, the mouse slows down and the absolute controllers get stickier, so it's easier to stop where you mean to.
  • Volume buttons: with only two buttons, A catches and B throws; holding A and pressing B pulls down a row; holding both for two seconds pauses.
Step 4

Menus without a d-pad

Outside play, movement is counted up and turned into single d-pad taps written into the game's own "held" and "pressed" button words. Every menu, the name entry and the Options screen react just as they would to a pad. Character select gets special care: the mouse and NeGcon walk the cards in reading order, and the Volume knob becomes a dial where every card has its own slice of the turn. Options gains a MOUSE SPEED row drawn with the game's own text routine.

Step 5

Finding room for about 6 KB of new code

The game fills the PlayStation's memory, so there was no empty space to add code. The build script maps every function the game can possibly call, starting from the entry point and following every pointer. Library functions that nothing ever reaches are free to reuse. Recorded play sessions double-checked that none of them ever ran. The new code is split into 20 small pieces that a packer fits into those gaps automatically, so moving one piece never means rewriting addresses by hand.

Step 6

60 Hz and English start

The game's timers count frames, so on a 50 Hz PAL console it runs about 17% slower than its designers intended. The NTSC build switches the video mode and screen position to 60 Hz, which brings back full speed with no other changes. The English-start option replaces the call that shows the flag screen with "English", so the game loads straight in.

Step 7

Testing

Every feature was tested in a scripted emulator: the scripts drive a virtual mouse, NeGcon, Volume or spinner, and check the game's memory to confirm where the clown is, which card is picked or whether the game paused, instead of trusting screenshots. Every language and every build goes through it. A checker also scans the code for the PlayStation CPU's timing rules (a value loaded from memory isn't ready for the very next instruction). The emulator is forgiving about this, so two such bugs slipped through before the checker existed; it now runs on every build.

This page

How the patcher works

Everything happens in your browser, in a background worker. A CHD is decompressed hunk by hunk (LZMA, Deflate and FLAC, with the CD error correction regenerated) and its checksum compared with the Redump dump before anything is changed. For CHD output, untouched hunks are copied straight from your file, and only the handful that changed are rewritten, so a new 200 MB CHD comes out in under a minute. The result is wrapped in an uncompressed ZIP so a BIN and its CUE arrive together.

SKIPLANG and NTSC must always be passed with -equ: armips refuses .ifndef defaults and equ inside .if, so derived constants are written as expressions (VHOLDN equ 100 + NTSC*20).

How build.py places the code

  • Hook sites are found in each language EXE by masked signatures taken from MD3EN (immediates and jump targets masked); the original instructions are verified before writing. The EN addresses are the G_* table at the top of tools/build.py and become syms_XX.asm includes.
  • Free space: functions no path from the entry point or any pointer-like word reaches, at least 0x40 bytes and starting at an addiu sp,sp,-n prologue, plus the EXE tail 0x8010A8E0–0x8010B000 (the heap-start lui at 0x80063684 now points at 0x8010B000 so InitHeap stops writing there).
  • The asm is split into chunks marked ;@chunk name: cfg, state, padinit, padread, padone, padneg, padnegb, padvol, padvplay, tick, tick2, tick3, vol, volcard, clown, glide, cell, cursor, opt, name (20 chunks, about 6 KB). Each is measured, then packed best-fit largest-first with a backtracking search; build_log.json records every placement.
  • Chunks land anywhere, so cross-chunk branches go through a local j trampoline, and a chunk entered with jal returns a status in v1 (0 done, 1 continue as mouse at @@mbtn, 2 failed read) instead of jumping into the caller's @@ labels (a static @label also ends the @@ scope).
  • If a new chunk won't fit, split chunks below the size of the ninth-largest hole; total space (8.5–9.8 KB per language) has never been the limit, fragmentation has.

Controller rules

  • Raw buffer: byte 0 status (0 = good), byte 1 ID (0x41 digital, 0x73 analog, 0x12 mouse, 0x23 NeGcon/Volume), then active-low buttons and analog bytes. The ID byte is cleared after each read; still 0 next time = stale, repeat ST_LAST.
  • Failed read: repeat the last word, keep all detection state; 30 in a row = unplugged (resets JP3 and Volume/NeGcon). An 0x23 read with I, II and L all ≥ 0xF0 counts as failed.
  • 0x23 is a Volume until NeGcon-only input (I/II/L past cfg_nthr 0x60, or any button other than START/CIRCLE) shows with an overlapping mask on 3 consecutive reads. Volume A = START bit, B = CIRCLE bit; knob in byte 4.
  • JP3: first read with LEFT+RIGHT latches; position = A xor 3B; delta 2 counts as two edges in the last direction; cfg_jcnt (8) mouse counts per edge.
  • Volume in play: A then B = pull down, both held VHOLDN (100 PAL / 120 NTSC) = pause; in menus knob = up/down, B + knob = left/right, B tap = △, A+B = START.

Tuning block

A 44-byte block starting "PDCF" in the cfg chunk holds every constant (offsets in the asm comments): menu step 20 counts, name step 8, hysteresis 8, settle 8, power-on speed, magnet, pulse, glide, NeGcon dead zone/range/repeat/threshold, JP3 counts, speed table 1/2/4/8, pulse table, Volume range vlo/vhi 0x00/0xFF and step 2. Its address moves per build: build/pal/build_log.json lists, per language, every resolved G_* symbol and each chunk's address and size (cfg included).

Tests

test/retro.py drives PCSX-ReARMed through libretro (PCSX_CORE; the interpreter build with pcsx_rearmed_debug_hooks.diff adds breakpoints, watchpoints and coverage). Scripts: langtest (all six languages), jp3test, voltest, volmenu, volchord, glitchtest, mkstates, seq. Assert from RAM via the build's symbols, rebuild savestates after any code move, and remember that switching a port's device in the emulator triggers the game's controller-removed pause. The NeGcon device in that core is 0x305; the Volume is tested as a NeGcon that never sends NeGcon-only input.

Pitfalls already paid for

  • Load delay: never use a loaded register in the next executed instruction, including a branch target when the load is in a delay slot. The emulator hid two of these.
  • Two instructions between mflo/mfhi and the next mult/div; no pseudo-ops (la, lw r,label) in delay slots.
  • A+B in menus must stay START; the Volume B modifier must not swallow it or send △ on release.

Open items

  • Character select: Volume B should pick the alternate colour; waiting on which pad button the game uses for it.
